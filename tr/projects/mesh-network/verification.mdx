---
title: "Doğrulama"
description: "T3 Gemstone O1 üzerinde doğrudan IBSS bağlantılarını ve çok atlamalı BATMAN-adv iletimini doğrulayın"
---

Bu bölümde yapılandırılan ağın gerçekten birden fazla kablosuz atlama üzerinden trafik ilettiği doğrulanmaktadır.

Mesh ağ üç düğümle sınırlı değildir. Aşağıdaki prosedürde **üç T3 Gemstone O1 kartı test edilen doğrulama topolojisi olarak** kullanılmıştır.

Doğrulama iki farklı davranışı birbirinden ayırır:

- IBSS bağlantıları üzerinden doğrudan iletişim
- BATMAN-adv mesh üzerinden çok atlamalı iletişim

Bu ayrım önemlidir çünkü yalnızca başarılı bir uçtan uca ping sonucu, hedefe doğrudan mı yoksa bir ara mesh düğümü üzerinden mi ulaşıldığını tek başına göstermez.

## 1. Test Topolojisi

Test edilen fiziksel topoloji:

```text
Düğüm 1 <------> Düğüm 2 <------> Düğüm 3

Düğüm 1 <---------- X ----------> Düğüm 3
```

Test sırasında:

- Düğüm 1, Düğüm 2 ile doğrudan iletişim kurabilmiştir.
- Düğüm 2, Düğüm 3 ile doğrudan iletişim kurabilmiştir.
- Düğüm 1 ile Düğüm 3 arasında doğrudan kablosuz erişim gözlemlenmemiştir.

Doğrudan bağlantı ağı ile mesh ağı ayrı tutulmuştur:

```text
wlan0 / IBSS: 192.168.100.N/24
bat0 / Mesh:   192.168.200.N/24
```

Bu sayede doğrudan IBSS erişimi ile BATMAN-adv mesh erişimi karşılaştırılabilir.

## 2. Doğrudan IBSS Erişimini Doğrulayın

BATMAN-adv davranışını değerlendirmeden önce `192.168.100.x` adresleri üzerinden doğrudan IBSS topolojisini doğrulayın.

Kurulum bölümündeki IBSS yapılandırması üç düğümde de aktif olmalıdır.

### Düğüm 1

Düğüm 2'yi test edin:

```bash
ping -c 5 192.168.100.2
```

Gözlemlenen sonuç:

```text
Başarılı
```

Düğüm 3'ü test edin:

```bash
ping -c 5 192.168.100.3
```

Gözlemlenen sonuç:

```text
Başarısız
```

### Düğüm 3

Düğüm 2'yi test edin:

```bash
ping -c 5 192.168.100.2
```

Gözlemlenen sonuç:

```text
Başarılı
```

Düğüm 1'i test edin:

```bash
ping -c 5 192.168.100.1
```

Gözlemlenen sonuç:

```text
Başarısız
```

Bu sonuçlar test sırasında gözlemlenen doğrudan IBSS erişimini gösterir:

```text
Düğüm 1 <------> Düğüm 2 <------> Düğüm 3

Düğüm 1 <---------- X ----------> Düğüm 3
```

IBSS doğrudan kablosuz bağlantıları sağlamıştır ancak test edilen fiziksel topolojide iki uç düğüm birbirine doğrudan erişememiştir.

## 3. BATMAN-adv Komşularını Doğrulayın

Kurulum bölümündeki BATMAN-adv yapılandırmasını üç düğümde de tamamlayın.

Mesh durumunun yakınsaması için bekleyin:

```bash
sleep 15
```

Düğüm 1 üzerinde:

```bash
sudo batctl n
```

Testte Düğüm 1, Düğüm 2'yi doğrudan BATMAN-adv komşusu olarak göstermiştir.

Düğüm 2 üzerinde:

```bash
sudo batctl n
```

Testte Düğüm 2 her iki uç düğümü de doğrudan komşu olarak göstermiştir.

Düğüm 3 üzerinde:

```bash
sudo batctl n
```

Testte Düğüm 3, Düğüm 2'yi doğrudan komşu olarak göstermiştir.

Gözlemlenen komşuluk topolojisi:

```text
Düğüm 1 <------> Düğüm 2 <------> Düğüm 3
```

## 4. İletim Yolunu Doğrulayın

Düğüm 1 üzerinde originator tablosunu inceleyin:

```bash
sudo batctl o
```

Testte Düğüm 3 bilinen bir originator olarak görünmüş ve Düğüm 2, Düğüm 3'e doğru sonraki atlama olarak seçilmiştir.

Kavramsal olarak:

```text
Hedef:          Düğüm 3
Sonraki atlama: Düğüm 2
```

Aynı kontrolü Düğüm 3 üzerinde tekrarlayın:

```bash
sudo batctl o
```

Düğüm 1'e doğru sonraki atlama olarak Düğüm 2 seçilmelidir.

Bu bilgi BATMAN-adv'in uzak uç düğüme ara düğüm üzerinden bir yol öğrendiğini gösterir.

## 5. Çok Atlamalı Yolu İzleyin

Düğüm 1'den Düğüm 3'e doğru BATMAN-adv yolunu, Düğüm 3 originator MAC adresini kullanarak izleyin:

```bash
sudo batctl tr <NODE3_MAC>
```

Gözlemlenen yol Düğüm 3'ten önce Düğüm 2'yi içermelidir:

```text
Düğüm 2
Düğüm 3
```

BATMAN-adv katmanında doğrudan bağlantı testi de yapılabilir:

```bash
sudo batctl ping <NODE3_MAC>
```

Bu komutlar IP seviyesindeki ping testinden bağımsız olarak mesh yolunu inceler.

## 6. Uçtan Uca Mesh Trafiğini Test Edin

BATMAN-adv aktif durumdayken `bat0` adresleri üzerinden iletişimi test edin.

Düğüm 1'den:

```bash
ping -c 5 192.168.200.3
```

Gözlemlenen sonuç:

```text
Başarılı
```

Düğüm 3'ten:

```bash
ping -c 5 192.168.200.1
```

Gözlemlenen sonuç:

```text
Başarılı
```

Doğrudan IBSS testi ile mesh testi karşılaştırıldığında:

```text
Doğrudan IBSS:

Düğüm 1 --------------- X ---------------> Düğüm 3


BATMAN-adv:

Düğüm 1 -----------> Düğüm 2 -----------> Düğüm 3
```

Test edilen IBSS topolojisinde Düğüm 1 ile Düğüm 3 arasında doğrudan erişim gözlemlenmemiş, BATMAN-adv etkinleştirildikten sonra ise `bat0` adresleri arasındaki iletişim başarılı olmuştur.

`batctl n` ve `batctl o` sonuçlarıyla birlikte değerlendirildiğinde bu durum, uç düğümler arasındaki trafiğin Düğüm 2 üzerinden iletildiğini doğrular.

## 7. Sonuç

Üç düğümlü test şu doğrulama zincirini üretmiştir:

1. Düğüm 1, IBSS üzerinden Düğüm 2'ye doğrudan erişebilmiştir.
2. Düğüm 3, IBSS üzerinden Düğüm 2'ye doğrudan erişebilmiştir.
3. Test edilen fiziksel topolojide Düğüm 1 ile Düğüm 3 arasında doğrudan IBSS erişimi gözlemlenmemiştir.
4. `batctl n`, beklenen doğrudan komşuluk ilişkilerini göstermiştir.
5. `batctl o`, uzak uç düğüme doğru sonraki atlama olarak Düğüm 2'yi göstermiştir.
6. `batctl tr`, ara mesh atlamasını göstermiştir.
7. Uç düğümlerin `bat0` adresleri arasındaki iletişim başarılı olmuştur.

Doğrulanan iletim yolu:

```text
Düğüm 1 ------> Düğüm 2 ------> Düğüm 3
```

ters yönde ise:

```text
Düğüm 3 ------> Düğüm 2 ------> Düğüm 1
```

Bu sonuç, test edilen T3 Gemstone O1 topolojisinde alttaki IBSS kablosuz bağlantıları üzerinde BATMAN-adv ile Katman 2 seviyesinde çok atlamalı veri iletiminin çalıştığını doğrular.
