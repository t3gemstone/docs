<Warning>
لا يزال دعم NuttX للوحة Gemstone قيد التطوير. لا يمكن بعد استخدام بعض الوحدات الطرفية الموجودة على اللوحة مثل
ناقل CAN.
</Warning>

NuttX هو نظام تشغيل مفتوح المصدر مصمَّم لتطبيقات الوقت الفعلي. يتميز NuttX، المتوافق مع معايير POSIX و ANSI،
بتحسينه خصيصاً للأنظمة المدمجة والمتحكمات الدقيقة. السبب الأساسي لاختيارنا NuttX لنوى R5F الموجودة على لوحة
Gemstone هو سلوكه الحتمي وقدرته على إدارة مهام الوقت الفعلي بشكل موثوق. كما أن NuttX منصة مدعومة من برمجيات
الطيار الآلي الشائعة مثل ArduPilot و PX4، مما يجعله ذا أهمية حاسمة لمشاريع الطائرات المسيّرة والمركبات ذاتية
القيادة.

نظراً لعدم وجود دعم رسمي لـ NuttX لمنظومة AM67A SoC حتى الآن، أُنشئت إعدادات `nsh` خصيصاً في المجلد
`boards/arm/am67/t3-gem-o1`. وبفضل هذه الإعدادات، يمكن تشغيل NuttX على نوى R5F المناسبة لعمليات الوقت الفعلي
الموجودة على لوحتنا.

## 1\. التجميع

### 1\.1\. تثبيت المتطلبات وسلسلة الأدوات (Toolchain)

لتجميع NuttX يجب توفر متطلبات مختلفة في النظام. كما نحتاج إلى مترجم متقاطع (cross compiler) متوافق مع نوى
ARM Cortex-R5F. تعد سلسلة الأدوات `gcc-arm-none-eabi` الحل القياسي الذي يلبي هذه الحاجة.

على أنظمة Ubuntu/Debian يمكنك تثبيت المتطلبات وسلسلة الأدوات عبر مدير الحزم:

```bash
sudo apt update
sudo apt install \
    bison flex gettext texinfo libncurses5-dev libncursesw5-dev xxd \
    git gperf automake libtool pkg-config build-essential gperf genromfs \
    libgmp-dev libmpc-dev libmpfr-dev libisl-dev binutils-dev libelf-dev \
    libexpat1-dev gcc-multilib g++-multilib picocom u-boot-tools util-linux \
    kconfig-frontends gcc-arm-none-eabi
```

بدلاً من ذلك، يمكنك إجراء تثبيت يدوي بتنزيل أحدث إصدار من سلسلة الأدوات من موقع ARM الرسمي. بعد التثبيت، يمكنك
التحقق من عمل سلسلة الأدوات بشكل صحيح باستخدام الأمر `arm-none-eabi-gcc --version`.

### 1\.2\. تنزيل أكواد المصدر

يتكون نظام NuttX البيئي من مستودعين أساسيين: نظام التشغيل الأساسي وإطار عمل التطبيقات. لتنزيل النسخ المخصصة
للوحة Gemstone، اتبع الخطوات التالية:

```bash
# استنسخ مستودع NuttX الرئيسي
git clone https://github.com/t3gemstone/nuttx.git

# استنسخ تطبيقات NuttX في مجلد 'apps'
git clone https://github.com/t3gemstone/nuttx-apps.git apps

# انتقل إلى دليل العمل الرئيسي
cd nuttx
```

ينشئ هذا الإعداد بنية الأدلة القياسية التي يتوقعها NuttX. يحتوي مجلد `apps` على التطبيقات والخدمات التي ستعمل
فوق نظام التشغيل.

### 1\.3\. تطبيق الإعداد الافتراضي

يستخدم NuttX إعدادات مُعدّة مسبقاً لمنصات عتاد مختلفة. لنبدأ بتطبيق الإعداد `t3-gem-o1:nsh` الخاص بلوحة Gemstone:

```bash
./tools/configure.sh -l t3-gem-o1:nsh
```

يضبط هذا الأمر الإعدادات الأساسية المناسبة لخصائص AM67A SoC ويفعّل واجهة سطر أوامر بسيطة تسمى NuttShell (nsh).
يتيح لك NuttShell إجراء عمليات الملفات الأساسية ومهام إدارة النظام.

### 1\.5\. تجميع المشروع

بعد اكتمال الإعداد، يمكننا تجميع NuttX:

```bash
make -j$(nproc)
```

يجري هذا الأمر تجميعاً متوازياً مستخدماً جميع نوى المعالج (CPU) الموجودة في نظامك. ينتج عن التجميع ملف ELF
باسم `nuttx`. يحتوي هذا الملف على صورة نظام التشغيل التي ستُحمَّل إلى نواة R5F.

### 1\.6\. تخصيص الإعداد

قد تحتاج أحياناً إلى إجراء تغييرات على الإعداد الافتراضي. يستخدم NuttX أداة `menuconfig` بشكل مشابه لنواة Linux.
من خلال هذه الواجهة الرسومية يمكنك تفعيل المشغّلات أو تغيير إعدادات الذاكرة أو إضافة ميزات جديدة. تُحفظ
التغييرات التي تجريها في ملف `.config`.

```bash
make menuconfig
```

لجعل تغييراتك دائمة وإمكانية إضافتها إلى نظام التحكم في الإصدارات، استخدم الأمر `savedefconfig`. يحفظ هذا الأمر
فقط الإعدادات المختلفة عن الإعدادات الافتراضية، وبذلك لا يتضخم ملف الإعداد بلا داعٍ. يمكنك نسخ ملف `defconfig`
الناتج عن الأمر إلى الإعداد الافتراضي المسمى `nsh` داخل المجلد `boards/arm/am67/t3-gem-o1/configs`، أو إنشاء
إعداد جديد باسم مختلف.

```bash
make savedefconfig
```

### 1\.7\. عمليات التنظيف

قد تحتاج أحياناً أثناء عملية التطوير إلى البدء من جديد بشكل نظيف. يوفر NuttX أمرين للتنظيف على مستويين:

```bash
# ينظف ملفات الكائنات والملفات الثنائية فقط
make clean

# ينظف جميع ملفات البناء والإعداد
make distclean
```

يحذف الأمر `make clean` الملفات الناتجة عن التجميع مع الحفاظ على الإعداد. أما `make distclean` فيعيد المشروع
بالكامل إلى حالته الأولى، وفي هذه الحالة ستحتاج إلى إعادة عملية الإعداد من جديد.

## 2\. التشغيل

بينما يعمل نظام التشغيل NuttX على نوى R5F، يعمل نظام التشغيل Linux على نوى A53. يمكن تحميل الأكواد إلى نوى R5F
عبر آلية `remoteproc` الموجودة في نظام التشغيل Linux وفي U-Boot.

<Tip>
   لاستخدام آلية `remoteproc` في U-Boot، يمكنك الاطلاع على قسم [2.8. تشغيل المشروع المجمَّع في مرحلة U-Boot](/ar/boards/o1/peripherals/mcu#2-8-تشغيل-المشروع-المجمع-في-مرحلة-u-boot).
</Tip>

يجب نسخ ملفات البرامج التي ستُحمَّل إلى النوى عبر remoteproc تحت المجلد `/lib/firmware` بأسماء معرّفة مسبقاً. عند
بدء النظام، ستحمّل آلية remoteproc البرامج تلقائياً إلى النوى المعنية. لتشغيل NuttX عبر remoteproc، اتبع الخطوات
التالية.

1. انسخ ملف `nuttx` الناتج عن التجميع إلى المجلد `/lib/firmware` باسم `j722s-main-r5f0_0-fw`.
2. أعد تشغيل اللوحة.
3. يمكنك الوصول إلى NuttShell بتوصيل جهاز USB-to-TTL إلى الطرفين GPIO-14 (TX) و GPIO-15 (RX) الخاصين بـ
   UART-MAIN1 والموجودين على HAT ذي الأربعين طرفاً.
4. من كونسول `nsh` الذي يظهر، يمكنك تشغيل البرنامج المسمى `blink` وملاحظة وميض مصابيح LED الخاصة بالمستخدم
   الموجودة على اللوحة.

## 3\. تصحيح الأخطاء (Debug)

### 3\.1\. تفعيل ميزات تصحيح الأخطاء

يُضبط NuttX افتراضياً في وضع release، مما ينتج ملف ELF صغير الحجم محسَّناً لكنه لا يحتوي على معلومات تصحيح
الأخطاء. لإجراء تصحيح أخطاء خطوة بخطوة أثناء عملية التطوير، ستحتاج إلى الانتقال إلى وضع تصحيح الأخطاء.

افتح أداة `menuconfig` واتبع المسار التالي: `Build Setup` → `Debug Options` → `Enable Debug Features`. كما يجب تفعيل
خيار `Generate Debug Symbols`. تتيح هذه الإعدادات للمترجم تضمين معلومات تصحيح الأخطاء داخل ملف ELF، مما يمكّن
المصحح (debugger) من إجراء تصحيح الأخطاء على مستوى الكود المصدري.

### 3\.2\. التكامل مع CCS IDE

يُعد Texas Instruments Code Composer Studio (CCS) بيئة تطوير محسَّنة خصيصاً لعائلة AM67A SoC. لدمج مشروع NuttX
الخاص بك في CCS، افتح IDE واستخدم الخيار `File` → `Import` → `C/C++` → `Existing Code as Makefile Project`. اختر
مجلد `nuttx` كدليل للمشروع.

### 3\.3\. تحميل البرنامج إلى النواة

لبدء عملية تصحيح الأخطاء عبر CCS IDE، أنشئ أولاً Target Configuration باختيار طراز Debug Probe الذي ستستخدمه
(على سبيل المثال Texas Instruments XDS200) واللوحة `J722S_TDA4VEN_TDA4AEN_AM67`. ثم شغّل Target Configuration واتصل
بـ AM67A SoC.

بعد إنشاء اتصال المصحح، اختر نواة Main R5F وحدد ملف `nuttx` ELF عبر `Run` → `Load` → `Load Program`. تحمّل هذه
العملية نظام التشغيل NuttX إلى ذاكرة نواة R5F.

بعد تحميل البرنامج، يمكنك وضع نقاط توقف (breakpoint) ومراقبة المتغيرات والتقدم خطوة بخطوة عبر الكود. بهذه الطريقة
يمكنك فحص كيفية عمل المكونات الحاسمة في NuttX مثل مجدول المهام (task scheduler) ومعالجات المقاطعة (interrupt
handler) بالتفصيل.
