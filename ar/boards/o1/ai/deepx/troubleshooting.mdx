title: 'استكشاف الأخطاء وإصلاحها'

---

يتضمن هذا القسم المشكلات الشائعة التي تواجهك أثناء تركيب وحدة المسرّع DX-M1 واستخدامها مع اقتراحات الحلول.

<AccordionGroup>

  <Accordion title="الوحدة لا تظهر في مخرجات lspci">

    عدم إدراج الوحدة في ناقل PCIe إطلاقاً يدل على أن المشكلة على مستوى العتاد.

    نفّذ الخطوات التالية بالترتيب.

    1. افصل طاقة اللوحة وأخرج الوحدة من منفذها ثم أعد تركيبها. تأكد من أن الوحدة مثبتة بالكامل في المنفذ وأن
       برغي التثبيت محكم.
    2. تحقق من أن محول الطاقة الذي تستخدمه قادر على تلبية إجمالي استهلاك اللوحة والوحدة. يؤدي التغذية غير
       الكافية إلى عدم تمكن الوحدة من إقامة اتصال PCIe.
    3. افحص سجلات النواة بحثاً عن أي خطأ متعلق باتصال PCIe.

    ```bash
    sudo dmesg | grep -i pcie
    ```
  </Accordion>

  <Accordion title="وحدات المشغّل لا تُحمَّل">

    إذا كان الأمر `lsmod | grep dx` يعطي مخرجات فارغة، فهذا يعني أن المشغّل لم يُحمَّل في النواة.

    تحقق أولاً مما إذا كان المشغّل ينتج خطأً أثناء محاولة تحميله.

    ```bash
    sudo dmesg | grep -i dxrt
    ```

    يمكنك محاولة تحميل المشغّل يدوياً.

    ```bash
    sudo modprobe dxrt_driver
    ```
  </Accordion>

  <Accordion title="ظهور خطأ صلاحية الوصول إلى ملف الجهاز">

    يدل خطأ `Permission denied` على أن المستخدم لا يملك صلاحية الوصول إلى ملف الجهاز الذي أنشأه المشغّل.

    يمكنك تشغيل التطبيق مؤقتاً بمستخدم مخوّل.

    ```bash
    sudo dxrt-cli -s
    ```

    للحصول على حل دائم، يمكنك فحص مالك ملف الجهاز وصلاحياته وإضافة مستخدمك إلى المجموعة المعنية.

    ```bash
    ls -l /dev/dxrt*
    ```
  </Accordion>

  <Accordion title="ظهور خطأ EFAULT أثناء الاستدلال">

    في تطبيقات Python، قد تواجه هذا الخطأ عند إنشاء مخزن الإدخال باستخدام `np.zeros()`. تشير جميع صفحات الذاكرة
    الافتراضية المخصصة عبر `np.zeros()` إلى نفس الصفحة الفيزيائية، وينتج مشغّل PCIe DMA خطأً عندما يرى نفس
    الصفحة الفيزيائية أكثر من مرة.

    أنشئ مخزن الإدخال بالصيغة التالية.

    ```python
    buffer = np.empty(ie.get_input_size(), dtype=np.uint8)
    buffer.fill(0)
    ```
  </Accordion>

  <Accordion title="الإبلاغ عن عدم توافق الإصدارات عند تحميل النموذج">

    يتحقق وقت تشغيل DX-RT من إصدار تجميع النموذج الذي يتم تحميله. يؤدي تجميع النموذج بإصدار DX-COM أقدم من وقت
    التشغيل الموجود على اللوحة إلى هذا الخطأ.

    تحقق من الإصدارات المثبتة.

    ```bash
    dxrt-cli -v
    ```

  </Accordion>

  <Accordion title="الحصول على معدل أطر أقل من المتوقع">

    عادةً ما يعود انخفاض معدل الأطر دون المتوقع إلى خطوات خارج NPU.

    حدد أولاً مكان الاختناق. لقياس الأداء الخالص للنموذج على NPU، يمكنك استخدام أداة القياس.

    ```bash
    run_model -m model.dxnn -b -l 100 -v
    ```

    إذا كان هذا القياس يعطي القيم المتوقعة بينما يعمل تطبيقك ببطء، فإن الاختناق يكون في خطوات المعالجة المسبقة
    أو المعالجة اللاحقة أو العرض. في هذه الحالة يمكنك مراعاة ما يلي:

    - استخدم القالب غير المتزامن بدلاً من القالب المتزامن. وبذلك يمكن لوحدة المعالجة المركزية (CPU) تحضير
      الإطار التالي بينما يجري NPU الاستدلال.
    - عطّل العرض المرئي.
    - استخدم بدائل C++ بدلاً من خطوات المعالجة اللاحقة المكتوبة بـ Python.

    إذا كان القياس منخفضاً أيضاً، فتحقق من درجة حرارة الوحدة.

    ```bash
    dxrt-cli --monitor 1
    ```

    <Warning>
      في حال بقاء درجة الحرارة مرتفعة، يخفض العتاد تردد الساعة بهدف حماية نفسه. وفي هذه الحالة يجب عليك تحسين
      تهوية الوحدة أو استخدام مشتت حراري.
    </Warning>
  </Accordion>

  <Accordion title="النموذج يعمل بشكل صحيح لكن النتائج خاطئة">

    لا يضمن نجاح عملية التجميع أن النموذج سينتج نتائج صحيحة. لهذه الحالة سببان شائعان.

    - **عدم توافق المعالجة المسبقة:** يجب أن تكون خطوات المعالجة المسبقة المعرّفة في ملف الإعداد أثناء التجميع
      مطابقة تماماً للخطوات المطبقة أثناء التدريب. تؤدي الاختلافات في تحويل فضاء الألوان وقيم التطبيع وطريقة
      التحجيم إلى نتائج خاطئة.
    - **عدم كفاية مجموعة بيانات المعايرة:** عدم تمثيل الصور المستخدمة أثناء التكميم (quantization) للبيئة التي
      سيعمل فيها النموذج يؤدي إلى انخفاض ملحوظ في الدقة.

    للتحقق من مخرجات النموذج، يمكنك مقارنة نتيجة نموذج ONNX على الكمبيوتر بنتيجة NPU باستخدام نفس المدخل.
  </Accordion>

  <Accordion title="لا يمكن لأكثر من تطبيق استخدام NPU في الوقت نفسه">

    إذا كانت أكثر من عملية (process) ستستخدم NPU في الوقت نفسه، فيجب أن تكون خدمة `dxrt` التي تدير مشاركة الموارد
    قيد التشغيل.

    ```bash
    systemctl status dxrt
    ```

    إذا لم تكن الخدمة قيد التشغيل، فابدأها وفعّلها لتبدأ تلقائياً عند الإقلاع.

    ```bash
    sudo systemctl enable --now dxrt
    ```
  </Accordion>

  <Accordion title="الرغبة في تركيب كل من SSD والمسرّع في منفذ M.2">

    يوجد منفذ M.2 2280 واحد فقط على لوحة التطوير T3 Gemstone O1. لذلك لا يمكن استخدام قرص NVMe SSD ووحدة المسرّع
    DX-M1 في الوقت نفسه.

    إذا كنت بحاجة إلى مساحة تخزين إضافية، فيمكنك استخدام منفذ بطاقة microSD أو وحدة تخزين متصلة عبر USB.
  </Accordion>

</AccordionGroup>

## الدعم

إذا لم تكن مشكلتك مذكورة في هذا القسم، فيمكنك طلب الدعم عبر [منتدى مجتمع T3 Gemstone](https://community.t3gemstone.org).
إضافة المعلومات التالية عند المشاركة يساعد على حل المشكلة بشكل أسرع.

```bash
uname -a
lspci
lsmod | grep dx
dxrt-cli -s
dxrt-cli -v
```
